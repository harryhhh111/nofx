# 基于 nofx 经验的长期量化交易系统设计方案

> 基于 `nofx-opt` 的工程资产、实盘教训与当前 AI 交易系统暴露的问题，设计一个独立但可复用 nofx 能力的长期量化交易系统。目标不是短期替换 nofx，而是建立 research/backtest-first 的策略研发、验证、执行与复盘闭环。

---

## 一、核心定位

这个系统不应只是把 nofx 的 AI 决策换成几条代码规则。

更准确的定位是：

```text
nofx 提供交易工程骨架
量化系统补齐研究、回测、特征、组合风控和策略评估闭环
```

因此它应该是一个长期分支：

- 可以复用 nofx 的交易所 adapter、paper trading、账户/仓位、风控配置和日志能力。
- 不继承 nofx 以 AI 为主决策中心的主循环。
- 不让 AI 直接决定开平仓。
- 所有策略必须先经过数据验证、回测、模拟盘，再进入小资金实盘。
- AI 只作为研究助手、异常解释器和复盘辅助，不进入核心下单路径。

---

## 二、目标校准：先追求可验证正期望，不追求高日化

首先必须对齐预期：

> 日化 **0.5%**，复利一年：`(1 + 0.005)^365 ≈ 12.9 倍`

这是极高难度目标，不适合作为系统初期稳定目标。

### 更合理的阶段目标

| 阶段 | 核心目标 | 收益目标 | 风险目标 |
|---|---|---|---|
| Research | 回测可信 | 不设收益目标 | 数据完整、费用/滑点模型可信 |
| Paper | 模拟稳定 | 日化 0% 以上即可 | 回撤 < 3%，paper/live 行为一致 |
| 小资金 | 真实验证 | 日化 0.02% - 0.08% | 回撤 < 5%，手续费后正期望 |
| 扩展期 | 多策略组合 | 日化 0.05% - 0.15% | 策略相关性可控，回撤稳定 |
| 极端行情 | 额外收益 | 单日 0.3% - 0.5% | 只作为 bonus，不作为常态目标 |

初期不应问：

```text
这个系统每天能不能赚 0.5%？
```

而应先问：

```text
回测是否可信？
手续费后是否正期望？
paper trading 是否复现回测行为？
亏损是否来自已知策略失效，而不是工程错误？
```

## 三、从 nofx 复用什么，不复用什么

### 1. 建议复用的能力

| nofx 能力 | 复用价值 |
|---|---|
| 多交易所 adapter（Paper / Aster / Hyperliquid） | 减少执行层重复建设 |
| 策略配置与 `risk_control` | 复用风控参数管理和 UI 思路 |
| 账户、仓位、成交记录 | 用于 paper/live 统一状态管理 |
| 决策日志与交易日志 | 用于策略归因和复盘 |
| kline / OI / funding / BB MACD 数据 | 作为特征和策略输入 |
| BE、drawdown、entry guard 等风控经验 | 迁移为量化系统的组合风控模块 |

### 2. 不建议直接复用的范式

| nofx 范式 | 为什么不适合量化系统核心 |
|---|---|
| AI 直接输出 open/close | 不可稳定回测，输出不完全确定 |
| prompt 约束交易纪律 | 纪律应由代码强制执行 |
| 单次 reasoning 决定交易 | 量化系统需要策略版本、样本外验证和归因 |
| 先实盘再复盘 | 量化系统应先 research/backtest，再 paper/live |

### AI 的位置

AI 可以参与：

- 生成策略研究假设。
- 解释异常行情和非结构化信息。
- 总结每日/每周复盘。
- 对比不同策略表现，提出待验证问题。
- 辅助写研究脚本和分析报告。

AI 不应参与：

- 直接决定某一笔 live 交易是否开仓。
- 绕过风控。
- 临场修改策略参数。
- 在没有回测证据时提高仓位。

## 五、策略设计原则

### 1. 策略必须声明适用市场状态

每个策略都必须回答：

- 适合趋势市、震荡市，还是高波动突破？
- 失效条件是什么？
- 哪些 regime 下必须禁用？
- 手续费和滑点后是否仍有空间？

例如：

| 策略 | 适用状态 | 禁用状态 | 主要风险 |
|---|---|---|---|
| 布林带均值回归 | 震荡、低到中等波动 | 强趋势、单边突破 | 接飞刀、连续止损 |
| 趋势首次回调 | 明确趋势、回调未破结构 | 震荡、趋势末端 | 追在末端、假回踩 |
| 波动率收缩突破 | 低波动后放量突破 | 高频假突破、流动性差 | 滑点、手续费、假突破 |

### 2. 策略只输出 signal，不直接下单

策略输出应类似：

```json
{
  "strategy": "boll_mean_reversion",
  "symbol": "BTCUSDT",
  "side": "long",
  "entry": 65000,
  "stop_loss": 64750,
  "take_profit": 65400,
  "confidence": 0.72,
  "regime": "range",
  "reason": "price touched lower band, RSI oversold, ADX low"
}
```

最终是否执行，由 `Portfolio & Risk` 决定：

- 今日是否已达最大亏损？
- 该币种/方向是否冷却？
- 账户总风险是否超限？
- R:R 是否足够？
- 手续费和滑点后是否还有正期望？
- 当前是否已有相关性过高的持仓？

### 3. 先少策略，后组合

不要同时启动三个策略。

建议顺序：

1. 先做一个最容易解释和回测的策略。
2. 验证回测、paper、实盘小资金是否一致。
3. 再加入第二个互补策略。
4. 最后再做策略组合和资金分配。

## 六、候选策略建议

### 策略 A：布林带均值回归

**定位**：第一个 MVP 策略。

**适用状态**：

- 低到中等波动。
- ADX 不高。
- 价格在区间内反复回归。

**基础逻辑**：

- 价格触及布林下轨 + RSI 偏低 → 候选做多。
- 价格触及布林上轨 + RSI 偏高 → 候选做空。
- 止盈目标：中轨或区间内可验证结构位。
- 止损：外轨之外加 ATR buffer。
- 时间止损：若 N 根 K 线内不回归，则退出。

**必须先验证的坑**：

- 强趋势中会连续接飞刀。
- 低周期手续费可能吃掉全部边际。
- 触碰布林带不等于一定回归。
- 回测必须加入滑点、手续费和资金费率。

### 策略 B：趋势首次回调

**定位**：第二阶段策略，不进 MVP 第一版。

**适用状态**：

- 1h/4h 趋势明确。
- 回调没有破坏结构。
- 回调后动能重新恢复。

**基础逻辑**：

- 大周期确认趋势。
- 小周期等待第一次回踩 EMA20 或结构位。
- 回踩不破 + 动能恢复 → 顺势 signal。
- 止损放在回踩结构外侧。
- 止盈看前高/前低或 trailing stop。

**主要风险**：

- 趋势末期追在最后一段。
- “第一次回调”的定义容易过拟合。
- 需要结构位和多周期一致性支持。

### 策略 C：波动率收缩突破

**定位**：观察策略，不建议早期实盘。

**适用状态**：

- 波动率显著收缩。
- 成交量/OI 支持突破。
- 标的流动性足够好。

**基础逻辑**：

- BOLL bandwidth 或 ATR 降至近期低位。
- 放量突破区间。
- 快速失败则退出。

**主要风险**：

- 假突破多。
- 滑点和手续费敏感。
- 需要更精细的成交和盘口数据。

## 七、回测优先级高于策略数量

量化系统第一阶段最重要的不是策略，而是回测可信度。

### 回测框架必须支持

- 逐 K 线回放，不能偷看未来数据。
- 多周期特征按时间对齐。
- 手续费、滑点、资金费率。
- 止损/止盈在同一根 K 线内的触发顺序假设。
- 参数版本记录。
- 样本内、样本外、walk-forward 验证。
- 每笔交易可追溯到信号、特征、regime 和风控决策。

### 最小指标集

| 指标 | 用途 |
|---|---|
| total return | 总收益 |
| max drawdown | 回撤 |
| Sharpe / Sortino | 风险调整收益 |
| win rate | 胜率 |
| avg win / avg loss | 盈亏结构 |
| profit factor | 策略质量 |
| max consecutive loss | 连亏风险 |
| fee / gross profit | 手续费侵蚀 |
| performance by regime | 策略适用状态 |
| rejected signal performance | 风控是否有效 |

## 八、风控规则必须代码化

这些规则不属于策略 alpha，而是交易系统生存条件。

### 1. 每日交易预算

```go
maxDailyTrades := 3
maxDailyLossPct := 1.0
maxConsecutiveLoss := 2
```

### 2. 每笔固定风险

```go
riskPerTradePct := 0.25
positionSize := accountEquity * riskPerTradePct / stopDistancePct
```

初期建议风险更小，不要一开始使用 0.5% - 1% 单笔风险。

### 3. 强制退出

```go
if holdBars > maxHoldBars && pnlPct <= 0 {
    closePosition("time_stop")
}

if peakPnLPct >= breakevenTriggerPct {
    moveStopLossToBreakeven()
}

if peakPnLPct >= trailingStartPct && drawdownFromPeak >= trailingDrawdownPct {
    closePosition("trailing_stop")
}
```

### 4. 方向/币种级冷却

```go
if losses("BTCUSDT", "SHORT") >= 2 {
    cooldown("BTCUSDT", "SHORT", duration)
}

if losses("*", "SHORT") >= 3 {
    cooldown("*", "SHORT", duration)
}
```

### 5. 组合风险

- 同方向相关标的不能同时暴露过大。
- BTC/ETH/SOL 同向持仓需要按相关性折算总风险。
- 单个交易所风险敞口要有限制。
- 高资金费率环境下要降低持仓时间或禁用方向。

## 九、MVP 实施计划

### Phase 0：定义数据与回测边界

- 确定第一批标的：BTC/ETH。
- 确定第一批周期：5m/15m/1h。
- 导入最近 3-6 个月 kline。
- 明确手续费、滑点、资金费率假设。
- 建立数据缺口和异常价格检测。

### Phase 1：搭建独立回测框架

- 实现 bar-by-bar 回放。
- 实现策略 signal 接口。
- 实现 portfolio/risk 模块。
- 输出交易明细和指标报告。
- 跑通“无策略基线”和“随机信号基线”，验证框架没有明显偏差。

### Phase 2：验证策略 A

- 实现布林带均值回归。
- 加入 ADX/regime filter。
- 加入手续费、滑点、time stop。
- 做参数敏感性测试，避免只对一组参数有效。
- 只要手续费后不能稳定正期望，就停止进入 paper。

### Phase 3：Paper Trading

- 只交易 BTC/ETH。
- 每天最多 3 笔。
- 单笔风险不超过账户权益 0.25%。
- 跑 2-4 周。
- 对比 paper 结果与回测预期差异。

### Phase 4：小资金实盘

- 从 500-1000 USDT 开始。
- 每周复盘一次参数和市场状态。
- 不因短期盈利提高仓位。
- 至少运行 4-8 周再考虑扩大资金。

### Phase 5：加入第二策略

只有当策略 A 满足以下条件，才加入策略 B：

- 回测、paper、小资金实盘行为大体一致。
- 亏损原因可解释。
- 手续费后仍有正期望。
- 策略失效条件清晰。

## 十、AI 辅助工作流

AI 在新量化系统里可以很有用，但它的职责应换位。

### 1. 研究助手

- 根据复盘结果提出新假设。
- 帮助生成指标组合。
- 总结异常交易。
- 解释某段行情为何策略失效。

### 2. 报告助手

- 每日生成策略表现摘要。
- 每周输出 regime 维度表现。
- 汇总参数变更影响。
- 标记需要人工检查的异常交易。

### 3. 安全边界

AI 不允许：

- 在 live 中直接修改参数。
- 直接提高仓位。
- 绕过冷却、止损、最大亏损限制。
- 生成未回测策略并立即实盘。

---

## 十一、最重要的风险

### 1. 回测幻觉

如果回测没有处理费用、滑点、资金费率、多周期对齐和同 K 线触发顺序，结果可能完全不可用。

### 2. 过拟合

参数越多，越容易只适配历史行情。

早期应限制参数数量，并做样本外验证。

### 3. 低周期手续费侵蚀

scalping 的毛利润通常很薄。手续费、滑点、资金费率可能吃掉全部收益。

### 4. regime filter 失效

均值回归最怕强趋势；突破策略最怕震荡。状态机判断错时，策略会连续亏损。

### 5. paper/live 偏差

paper trading 可能低估滑点、成交失败和盘口冲击。进入小资金实盘后必须重新评估。

---

## 十二、下一步建议

1. 不急着实现三套策略，先搭建可信回测框架。
2. 第一版只做 BTC/ETH + 5m/15m/1h + 布林带均值回归。
3. 风控模块从第一天就加入，不要等策略盈利后再补。
4. 每个 signal 都记录特征快照、regime、风控决策和最终结果。
5. 用 paper trading 验证 2-4 周，再考虑小资金实盘。
6. AI 作为研究和复盘助手，不作为交易执行主体。

一句话总结：

> nofx 提供了交易工程基础；真正的长期量化系统，核心竞争力在于可信数据、可信回测、明确策略边界、组合风控和持续复盘。
