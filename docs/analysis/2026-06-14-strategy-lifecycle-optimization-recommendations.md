### 4. 原分析需要补充的关键事实

四个历史策略的风控配置如下：

| 交易员 | drawdown_min_profit | drawdown_trigger | drawdown_use_ai | consecutive_loss_brake | breakeven |
|--------|---------------------|------------------|-----------------|------------------------|-----------|
| h2 | 5% | 40% | false | 无 | 无 |
| harry h3 | 5% | 40% | false | 无 | 无 |
| harry t5 | 2% | 40% | false | 3 连亏冷却 3 周期 | 无 |
| t5-1 | 2% | 40% | false | 无 | 无 |

因此，原分析中“缺乏趋势动能衰竭退出机制”的结论方向是对的，但需要更精确：

1. 当时并不是完全没有浮盈保护，而是有 `drawdown_close`。
2. 这四个历史策略没有启用 `breakeven_protection`。
3. `drawdown_close` 使用的是“杠杆价格收益率”，不是账户收益率，也不是 USDT 浮盈。
4. 当前实现要求 `currentPnLPct > minProfitPct && drawdownPct >= triggerPct`，如果回撤过快导致当前收益率跌破 `minProfitPct`，保护反而不再触发。

这解释了为什么 t5-1 的 BTC 峰值浮盈 +225 USDT 却没有自动平仓：按代码口径，BTC 峰值约为 1.64% 杠杆价格收益率，低于 t5-1 的 2% 启动门槛。

## 根因再归纳

### 根因 A：风险信号没有代码级否决权

t5-1 的提示词写了“1h RSI7 < 20 禁止做空”，但 2026-06-09 15:04 的 BTC 开空仍然发生：

- 1h RSI7=13.62，满足禁止做空条件。
- AI 仍以多周期空头、ADX 强趋势、机构流出、R:R 达标为由开仓。

这说明 prompt 级硬规则不足以承担风控职责。只要最终 JSON 是 `open_short` 且通过后端基础校验，交易就会执行。

### 根因 B：R:R 可被“目标外推”绕过

当前后端会校验 R:R，但 hard floor 是 `min_risk_reward_ratio * 0.8`。当策略配置为 1.5 时，实际硬下限是 1.2。

这可以防止极端劣质交易，但不能防止 AI 把 TP 放到“前低下方”“布林下轨下方”等弱锚点位置，让 R:R 形式上达标。

### 根因 C：浮盈保护的状态机不完整

`drawdown_close` 当前更像“当前仍高于启动门槛时的回撤保护”，而不是“曾经达到峰值后的利润保护”。

问题在于：

- 峰值达到门槛后没有显式 armed 状态。
- 触发时仍要求当前收益率高于 `minProfitPct`。
- 如果利润从 +3.5% 快速跌到 +1.5%，已经发生明显回撤，但当前条件不再满足。

这会把最需要保护的“快速 V 反”漏掉。

### 根因 D：连续亏损刹车只解决交易频率，不解决入场质量

harry t5 因为有 3 连亏冷却机制而存活，但总收益仍缓慢下降。刹车机制降低了连亏斜率，却没有改变以下问题：

- 超卖追空仍会发生。
- R:R 外推仍会发生。
- 浮盈仍可能回吐。

因此刹车应保留，但不能作为主修复。

## 优化建议

### P0：把极端风险信号做成代码级入场门

新增一个后端 pre-trade guard，在 AI 决策解析后、下单前执行。

建议规则：

| 场景 | 禁止条件 |
|------|----------|
| 开空 | 1h RSI7 < 20 或 1h RSI14 < 30 |
| 开多 | 1h RSI7 > 80 或 1h RSI14 > 70 |
| 开空 | 当前价距离 15m/1h 可见支撑过近，且可见 TP 空间不足 |
| 开多 | 当前价距离 15m/1h 可见阻力过近，且可见 TP 空间不足 |
| 过渡市 | 1h ADX 位于 20-25 且主周期与 1h 信号冲突 |

实现方式：

1. 在 `kernel` 层产出每个候选币的 `EntryGuardContext`。
2. 在 `validateDecision` 中接入 guard 结果。
3. 若违反 hard deny，直接把 open decision 转为 `wait`，并在 reasoning 前追加 `[REJECTED] entry guard denied: ...`。

这样 t5-1 的 BTC 开空会被后端拒绝，而不是寄希望于 AI 自己遵守 prompt。

### P0：修复浮盈回撤保护状态机

将当前条件从：

```text
currentPnLPct > minProfitPct && drawdownPct >= triggerPct
```

改为：

```text
peakPnLPct >= minProfitPct && drawdownPct >= triggerPct && currentPnLPct > minProtectedProfitPct
```

建议默认：

- `minProfitPct`: 2%
- `triggerPct`: 35%-40%
- `minProtectedProfitPct`: 0.3%-0.5%

含义：

- 一旦峰值达到 2%，保护进入 armed 状态。
- 之后只要从峰值回撤达到阈值，即使当前收益率已经低于 2%，也应保护剩余利润。
- 只要当前仍为小幅正收益，就优先保住利润，而不是等到亏损。

这比单纯把 `minProfitPct` 调低更稳，因为它避免了刚浮盈一点点就频繁平仓。

### P0：默认启用 Breakeven Protection

历史四个策略都没有 `breakeven_protection`，而当前 t5-2 已经配置：

```json
{"enabled": true, "trigger_pct": 1}
```

建议：

1. 所有趋势跟踪策略模板默认启用 BE。
2. 对已有策略做一次迁移：当 `breakeven_protection` 缺失时，补默认值。
3. UI 中明确说明 `trigger_pct` 是杠杆价格收益率，不是账户收益率。

对 t5-1 这类交易，BE 至少可以把“明显浮盈后最终大亏”转化为“小亏/保本/小赚”。

### P1：把 TP 锚点限制在可验证结构位

当前 R:R 校验只知道数值，不知道 TP 是否合理。

建议给市场数据增加结构位列表：

```json
{
  "supports": [60827.7, 60593.75],
  "resistances": [61297, 61519.9, 61706.87],
  "boll": {"lower": 60593.75, "middle": 61706.87, "upper": 62820.0},
  "recent_swing_lows": [...],
  "recent_swing_highs": [...]
}
```

后端校验：

- TP 必须落在结构位附近，允许少量 ATR 容差。
- 禁止“前低下方很多”“布林下轨下方很多”这类无锚点外推。
- 如果 TP 超出最近结构位，要求有 breakout confirmation，否则拒绝。

### P1：把 R:R hard floor 从 80% 改成分层策略

现在 `min_risk_reward_ratio=1.5` 时，硬下限实际为 1.2。

建议：

- 普通趋势单：硬下限 = 配置值本身，即 1.5。
- 反转/均值回归：硬下限 = 1.2，但仓位降级。
- 过渡市：硬下限 = 2.0。
- 若 AI 低于配置值但高于 hard floor，必须自动降仓，而不是照常开最大仓位。

### P1：增加“趋势末期观望模式”

建议新增 cooling reason，不只按交易结果触发，也按市场状态触发：

触发条件示例：

- 15m/1h ADX 从 >40 连续下降 3 个周期。
- 价格贴近布林外轨。
- 1h RSI 极端。
- OI 增加但价格无法继续创新低/新高。
- 最近 N 次同方向入场均未触达 TP。

触发后：

- 暂停同方向开仓 N 个周期。
- 允许反向交易，但必须满足更高标准。
- 保留已有持仓的退出和 BE 管理。

### P1：让连续亏损刹车按“方向+币种”细分

当前刹车按全局连续亏损过滤开仓。建议增加细粒度状态：

- `BTCUSDT SHORT` 连续亏损，优先阻断 BTC 空单。
- `SHORT` 方向整体连续亏损，阻断所有做空。
- 不阻断已有持仓平仓。

这样能更准确地处理“空头趋势耗尽，但多头/震荡机会仍存在”的场景。

### P2：改进文档和监控口径

建议在分析页和策略配置页统一展示三种收益率：

1. USDT 浮盈。
2. 账户净值收益率。
3. 杠杆价格收益率（风控触发口径）。

这次误判的核心之一，是人看到“+225 USDT / +2.13% from start”会以为回撤保护应触发，但代码实际看的是杠杆价格收益率，BTC 峰值约 1.64%，低于 2% 门槛。

## 建议落地顺序

1. 修复 drawdown-close armed 状态机，避免峰值已达标后快速回撤漏保护。
2. 对所有 AI 趋势策略默认开启 BE，并迁移旧策略缺失配置。
3. 实现 RSI/支撑阻力/过渡市的后端 entry guard。
4. 增加结构位 TP 校验，减少 R:R 外推。
5. 将连续亏损刹车升级为方向/币种维度。
6. 在 UI 和分析文档中统一风控收益率口径。

## 对原分析文档的建议修订

原分析文档建议保留主结论，但做三处修订：

1. 将“没有任何浮盈保护”改为“当时有 drawdown-close，但没有 BE；drawdown-close 的触发口径和状态机不足以覆盖这类快速回撤”。
2. 将“第一天一定先浮盈”改为“样本内均出现早期浮盈；原因是趋势末期的残余动量和反弹后入场纪律”。
3. 将“风险信号权重为零”改为“风险信号没有代码级否决权，容易被趋势 checklist 覆盖”。
