# 基于现有经验的 Code-First 量化交易系统方案

> 基于 `nofx-opt` 当前架构、数据能力和实盘教训，提出一个以代码规则为核心、以 AI 为辅助的最小可行量化交易系统方案。目标：稳定捕获每日小盈利机会，控制回撤。

---

## 一、目标校准：0.5% 日化意味着什么？

首先必须对齐预期：

> 日化 **0.5%**，复利一年：`(1 + 0.005)^365 ≈ 12.9 倍`

这是世界顶级量化策略的回报水平，不适合作为稳定目标。

### 建议的分阶段目标

| 阶段 | 目标 | 说明 |
|---|---|---|
| 第一阶段 | 日化 **0.05% - 0.1%** | 夏普 > 1.5，最大回撤 < 5% |
| 第二阶段 | 日化 **0.1% - 0.2%** | 稳定运行 3 个月以上 |
| 第三阶段 | 日化 **0.2% - 0.3%** | 多策略 + regime filter 成熟后 |
| 极端行情 | 日化 **0.3% - 0.5%** | 不可持续，只作为 bonus |

如果本金 10,000 USDT：
- 0.05% 日化 = 每天 5 USDT，一年复利约 1.2 倍
- 0.1% 日化 = 每天 10 USDT，一年复利约 1.44 倍

这些数字虽然小，但风险可控、可复制。

## 二、为什么这个方案是可行的？

`nofx-opt` 已经具备大量可直接复用的能力：

| 已有能力 | 对量化系统的价值 |
|---|---|
| 多交易所 adapter（Paper / Aster / Hyperliquid） | 可以直接接入实盘和模拟盘 |
| 策略配置与风控框架 | `risk_control` 可以直接复用 |
| 仓位/权益/成交记录 | 有完整的历史数据用于回测 |
| 决策日志 | 可以分析 AI 什么时候对、什么时候错 |
| BB MACD / kline / OI / funding 数据 | 信号源已经有了 |

所以不是从 0 开始，而是**在现有骨架上替换一个更纪律化的信号层**。

## 三、系统架构：Code-First Scalping System

```text
┌─────────────────────────────────────┐
│  Layer 4: 交易执行与风控              │
│  - 下单、止盈、止损、时间止损          │
│  - 每日最大亏损限制、仓位上限            │
│  - 手续费/滑点监控                    │
└─────────────────────────────────────┘
              ↑
┌─────────────────────────────────────┐
│  Layer 3: 信号规则引擎                │
│  - 均值回归信号                       │
│  - 趋势突破信号                       │
│  - 波动率收缩/扩张信号                 │
│  - 只发 signal，不做主观判断           │
└─────────────────────────────────────┘
              ↑
┌─────────────────────────────────────┐
│  Layer 2: 市场状态机                  │
│  - 趋势市 / 震荡市 / 高波动 / 低波动    │
│  - 代码根据状态选择启用哪些策略          │
└─────────────────────────────────────┘
              ↑
┌─────────────────────────────────────┐
│  Layer 1: 数据层                      │
│  - kline, OI, funding, volume, quant   │
│  - 已有，直接复用                      │
└─────────────────────────────────────┘
```

**AI 的角色**：最多只用于 Layer 2 的"状态判断辅助"，而不是直接决定开平仓。

## 四、具体策略设计

### 策略 A：布林带均值回归（适合震荡市）

**逻辑**：
- 价格触及布林下轨 + RSI < 30 → 做多
- 价格触及布林上轨 + RSI > 70 → 做空
- 止盈：回到中轨
- 止损：跌破下轨/突破上轨再加一个 ATR buffer

**仓位**：固定 1% 风险

**出场规则**：
- 止盈 0.3% - 0.5%（实际价格移动约 0.1%-0.15%）
- 时间止损：15 分钟没动就离场
- 浮盈回撤 30% 就保本

**为什么适合当前系统**：

现有数据里很多"先盈后亏"其实发生在震荡市。AI 把每次反弹当趋势，代码可以直接识别"这是布林带边界"。

---

### 策略 B：趋势突破后的首次回调（适合趋势市）

**逻辑**：
- 当 1h/4h 形成明确趋势后，等 5m/15m 第一次回踩 EMA20
- 回踩不跌破 + RSI 从超卖区反弹 → 顺势开仓
- 止盈：下一个前高/前低
- 止损：回踩低点/高点下方

**仓位**：1.5% 风险

**出场规则**：
- 浮盈 0.5% 推止损到保本
- 趋势结构破坏（跌破 EMA20）离场

---

### 策略 C：波动率收缩突破（Volatility Squeeze）

**逻辑**：
- Bollinger Band 收窄到近期最低 + ATR 下降
- 放量突破上轨 → 做多；跌破下轨 → 做空
- 这种机会一天通常 1-2 次

**仓位**：1% 风险

**出场规则**：
- 目标 1:1 R:R
- 失败就快速止损

## 五、关键规则必须代码化

这些不能让 AI 决定。

### 1. 每日交易预算

```go
maxDailyTrades := 5          // 每天最多 5 笔
maxDailyLossPct := 1.5       // 当日亏损达 1.5% 停止交易
maxConsecutiveLoss := 2      // 连亏 2 笔后冷却
```

### 2. 每笔交易固定风险

```go
riskPerTrade := 0.5%         // 每笔最多亏本金的 0.5%
positionSize := riskPerTrade / (entry - stopLoss)
```

### 3. 强制出场规则

```go
if unrealizedProfitPct > 0.5% {
    moveStopLossToBreakeven()
}

if unrealizedProfitPct > 1.0% {
    trailingStop = peakProfit * 0.7   // 回撤 30% 利润就平
}

if holdTime > 30 min && profit < 0 {
    closePosition("time_stop")
}
```

### 4. 状态过滤

```go
if regime == "trending" {
    allowStrategy(["trend_pullback", "breakout"])
} else if regime == "ranging" {
    allowStrategy(["mean_reversion"])
} else {
    noTrade()
}
```

## 六、最小可行版本（MVP）实施计划

### Week 1：搭建回测框架
- 用 `trader_positions` 历史数据 + kline 数据
- 写一个独立回测脚本（Python 或 Go）
- 先跑策略 A（布林带均值回归）

### Week 2：策略 A 实盘模拟
- 在 Paper Trading 上跑
- 只交易 BTC/ETH（流动性好、费用低）
- 每天最多 3 笔

### Week 3-4：加策略 B、C + 状态机
- 加趋势回调和波动率突破
- 加 regime filter
- 看策略之间是否互补

### Week 5-6：严格风控 + 优化
- 加每日亏损限制
- 加手续费/滑点模型
- 调参数，目标是夏普 > 1.2，胜率 > 55%

### Week 7+：小资金实盘
- 从 1000 USDT 开始
- 跑 1 个月验证

## 七、为什么这套比现在的 AI 系统更适合"每日小盈利"？

| 维度 | 现在 AI 系统 | Code-First 量化系统 |
|---|---|---|
| 交易频率 | AI 决定，不稳定 | 代码控制，每天 3-5 次 |
| 出场纪律 | AI 经常扛单 | 代码强制止盈/止损 |
| 风险控制 | 靠提示词约束 | 代码硬限制 |
| 情绪影响 | AI 会追涨杀跌 | 无情绪，严格按规则 |
| 可重复性 | 同一个输入不同输出 | 完全确定，可回测 |
| 手续费损耗 | 较高 | 可精确控制 |

## 八、现实的预期

如果你按上面做，并且策略 A/B/C 中至少有一个在当前市场 regime 下有效，比较合理的预期是：

| 阶段 | 目标 | 条件 |
|---|---|---|
| 模拟盘 1 个月 | 日化 0.05% - 0.1%，回撤 < 3% | 单策略或双策略 |
| 小资金实盘 2 个月 | 日化 0.05% - 0.15%，回撤 < 5% | 策略有效 + 风控在线 |
| 稳定运行 6 个月 | 日化 0.1% - 0.2% | 多策略 + regime filter |
| 极端好行情 | 日化 0.3% - 0.5% | 不可持续，只作为 bonus |

**0.5% 日化稳定复利是不现实的**，但**某些天达到 0.5% 是可能的**。

## 九、下一步建议

1. **先别抛弃现有系统**，而是并行跑一个"规则化子系统"
2. 用 **Paper Trading** 验证 1 个月
3. 只交易 **BTC/ETH**（手续费和滑点最低）
4. 把 **出场规则写得比入场规则更严格**
5. 每天收盘后自动复盘：胜率、盈亏比、最大回撤、最大连胜/连败

可以立即开始的第一步：写一个基于现有 `nofx-opt` 数据结构的回测脚本，用策略 A（布林带均值回归）跑最近 1 个月历史数据，看效果。
