# AI 决策与代码规则的边界分析

> 基于 `nofx-opt` 项目近几天的实盘表现、决策日志、策略配置与代码实现，分析当前 AI 决策中哪些可以被代码替代，以及替代后的预期效果差异。

---

## 一、核心结论

**如果把"纪律性规则"全部交给代码，把"市场结构判断"留给 AI，整体效果大概率会更好。**

AI 当前决策里，约有 **60%-70%** 是可以被代码等价或更稳定地替代的，而这 60%-70% 恰恰是当前亏损的主要来源。

---

## 二、现在哪些本应是代码，却交给了 AI？

从日志和决策记录中可以看到，AI 的思维链里大量出现这类判断：

| AI 当前的决策 | 实际上能不能用代码做？ | 为什么该交给代码 |
|---|---|---|
| "ADX=47，趋势很强，追空" | ✅ 完全可以 | ADX > 阈值 + 价格 < EMA 就是趋势跟踪信号 |
| "RSI7=23 超卖，但趋势未结束，继续空" | ⚠️ 大部分可以 | RSI 阈值 + 趋势过滤可以写成规则 |
| "R:R > 1.5，满足入场条件" | ✅ 完全可以 | 代码直接计算 entry/SL/TP 的 R:R |
| "已经 3 连亏，减少交易频率" | ✅ 已经在代码里 | `consecutive_loss_brake` |
| "浮盈 5%，是否该保本？" | ✅ 已经在代码里 | `breakeven_protection` |
| "回撤 40%，是否平仓？" | ✅ 已经在代码里 | `drawdown_close` |
| "BTC/ETH/SOL 哪个更有机会？" | ⚠️ 部分可以 | 可以用动量排序、OI 变化、资金流向量化 |
| "这是趋势末端还是中继？" | ❌ 很难 | 需要综合结构、情绪、流动性，AI 有优势 |

---

## 三、AI 决策里到底有多少可被代码替代？

### 1. 已经由代码强制执行的部分（约 20%）

- 杠杆、仓位上限、保证金使用率
- 最大持仓数、最小 confidence
- `consecutive_loss_brake`、`drawdown_close`、`breakeven_protection`
- 止损触发后的 close reason 标记

这些已经是代码在兜底。

### 2. 应该用代码做，但现在还在让 AI "自觉" 的部分（约 45%）

这是亏损的主要来源。

#### a) 入场信号

AI 的开仓理由基本都是：
- 趋势方向（ADX + EMA + MACD）
- 超买/超卖（RSI）
- 多周期共振

这些都可以写成规则树。例如：

```python
if adx_15m > 25 and close < ema_20_5m and rsi_7_5m < 70:
    signal = SHORT
```

#### b) 退出信号

AI 现在只在两种情况下平仓：
- AI 主动判断 "趋势结束/目标达成"（高度主观，经常错）
- 硬止损被触发

代码可以补充：
- 趋势反转结构（比如价格回到 EMA 上方且 RSI 拐头）
- 动能衰竭（MACD 背离、成交量萎缩）
- 时间止损（持仓超过 N 周期无进展）

#### c) 币种选择

AI 看 "quant data / OI / netflow / price ranking"，但这些 ranking 本身就是代码算出来的。完全可以直接按动量排序选币。

### 3. 确实需要 AI 的部分（约 35%）

- **市场结构综合判断**：这是趋势末端还是中继？
- **异常环境识别**：暴跌后的反弹、消息驱动、流动性断裂
- **多因子权衡**：当多个指标冲突时，哪个权重更高？
- **对手盘行为**：从 OI、资金费率、大额流水中读出情绪

这些确实比硬规则更灵活。

---

## 四、为什么把更多规则交给代码会更好？

### 1. 代码不会"觉得"规则可以忽略

AI 的提示词里有很多"建议"：
- "RSI 极度超卖时应谨慎"
- "趋势末端应减少追单"

但 AI 的思维链里经常反过来做。因为它把"趋势信号"当成检查项，把"风险警告"当成建议项。

代码不会这样。代码是 `if rsi < 20 and trend != strong: skip()`。

### 2. 代码不会因为"想翻本"而乱开仓

看 `harry h5-2` 的日志：一笔 BTC 小赚后，连续追 ETH/SOL/BTC 多，全部被止损。这是典型的"盈利后过度自信"模式。

代码可以强制：

```python
if last_N_trades_loss_count >= max_loss_brake:
    no_trade_for_X_cycles()
```

### 3. 代码执行的退出更一致

AI 对"是否平仓"的判断高度依赖当时的心情式 reasoning。代码可以：
- 浮盈回撤 30% → 保本
- 趋势结构破坏 → 离场
- 持仓超时 → 减仓

### 4. 可回测、可优化

规则写出来之后，可以跑历史数据看哪些参数好。AI 的 prompt 很难量化回测。

## 五、但完全不用 AI 也会有问题

如果全用代码，会失去两种能力：

### 1. 非结构化信息的整合

比如：
- 链上大额转账
- 交易所公告
- 社交媒体情绪
- 宏观事件

这些可以通过 MCP/插件喂给 AI，让 AI 做"事件影响评估"。

### 2. 复杂结构识别

比如：
- "这是一个 bear flag 还是 bottoming wedge？"
- "当前是 liquidity grab 还是真突破？"
- "这个币为什么在大盘跌时抗跌？"

这些用硬规则很难覆盖所有变体。

## 六、推荐的混合架构：代码管纪律，AI 管模糊判断

```text
┌─────────────────────────────────────────┐
│  Layer 3: AI 模糊层（30-40%）            │
│  - 市场结构综合判断                      │
│  - 异常事件解读                          │
│  - 多周期叙事一致性                       │
│  输出：direction_bias, confidence, regime │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Layer 2: 规则引擎（40-50%）             │
│  - 趋势/反转/超买卖信号                   │
│  - R:R 验证                              │
│  - 币种筛选/排序                         │
│  输出：trade_signal, sl, tp              │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Layer 1: 硬风控（20-30%，已存在）       │
│  - 仓位、杠杆、margin、最大持仓           │
│  - BE、drawdown、time stop               │
│  - 连亏刹车、对冲检测                     │
│  输出：execute / block / modify          │
└─────────────────────────────────────────┘
```

### 具体落地建议

**第一步：把入场规则代码化**
- 定义趋势条件（ADX + EMA 方向）
- 定义反转条件（RSI 超买/超卖 + 背离）
- AI 只负责判断"当前是趋势市还是震荡市"（regime）
- 代码根据 regime 选择对应规则

**第二步：把退出规则代码化**
- 添加 `trailing_stop`、`time_stop`、`structure_break_exit`
- AI 只负责判断"趋势是否衰竭"作为附加信号

**第三步：把币种选择代码化**
- 用 quant ranking + momentum score
- AI 只负责黑名单/异常事件过滤

**第四步：保留 AI 的否决权，而不是决策权**
- AI 可以说"这个市场状态我不交易"
- 但 AI 不能绕过代码的风控开仓

## 七、直接回答

> 效果会相差多少？

如果目标是"稳定少亏"，代码化规则大概率比现在的 AI 主导好 **30%-50%**（按最大回撤或盈亏比衡量）。

如果目标是"捕捉大行情暴利"，纯代码可能不如好的 AI，因为 AI 能识别一些复杂结构。

> AI 决策里有多少可被代码替代？

- **60%-70% 可以替代**：主要是入场信号、风险纪律、退出触发
- **30%-40% 难以替代**：市场结构综合判断、异常环境识别

但这 60%-70% 是当前系统里**最重要、最该先修**的部分。先把这部分从 AI 手里拿回来，系统的生存率会高很多。

---

## 八、下一步建议

1. 先在 `docs/plans/` 中明确一份"规则化交易系统"的设计文档
2. 选择一个最小策略（如布林带均值回归）在 Paper Trading 上独立跑 2 周
3. 保留 AI 系统作为对照组，比较夏普、胜率、最大回撤
4. 如果代码化策略表现更稳定，再逐步把更多规则迁移到代码层
